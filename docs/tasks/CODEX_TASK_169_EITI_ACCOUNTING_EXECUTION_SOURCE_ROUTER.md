# TASK 169 — EITI primary municipal accounting execution source router

This task is T0/offline only. It does not select or authorize a new live municipal source.

## Why this task exists

TASK 122 proved that PPA, LOA and SIOPE/FUNDEB evidence still lack a stable key that binds the EITI policy to accounting execution. TASK 123 therefore required a primary granular execution surface. TASK 168 then closed two PNCP leads as a bounded-negative contract bridge: the purchases remain valid PNCP identities, but they did not produce a contract linkage in the fully paginated current contract scope.

The robot must therefore stop searching by weak thematic lead and define what the next accounting source must expose.

## Promotion logic

Policy-specific financial identity needs, at minimum:

- exact municipal entity/CNPJ;
- exact fiscal year;
- explicit EITI/Fomento-ETI policy linkage or an exact stable-key crosswalk to a primary policy document;
- institutional unit;
- program/action or more granular programmatic identity;
- a stable budget key such as ficha or dotação identifier;
- explicit amount semantic;
- a primary budget/accounting source role.

Program 2001 alone, unit-code similarity, C.Apl 2607004 alone, equal values, chronology, semantic similarity and PNCP procurement without an accounting link remain insufficient.

## Transaction logic

Even after policy financial identity is proven, execution stays split:

1. commitment requires an explicit empenho identity and committed amount;
2. liquidation requires a liquidation record or explicit liquidated amount linked to the same transaction identity;
3. payment requires a payment record or explicit paid amount linked to the same identity.

No stage substitutes for another.

## Source priority

1. Limeira primary transparency expense/empenho detail;
2. municipal accounting application/ficha/dotação search;
3. official Education cost-center/subaction execution report;
4. TCE/control granular source as corroboration, not a replacement for unresolved municipal policy identity.

DIRECT_JSON_FIRST remains mandatory.

## Authorization

TASK 169 performs zero network and zero Drive operations. The standing PNCP authorization does not extend to a municipal/accounting host. A future live gate must name the exact new host/source/purpose and receive fresh explicit owner authorization before execution.
