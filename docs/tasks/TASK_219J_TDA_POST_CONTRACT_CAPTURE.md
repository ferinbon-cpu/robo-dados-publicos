# TASK 219J — sanitized automatic TDA POST contract

Issue: #709  
Parent: #691

## Purpose

TASK 219I proved that the public Limeira TDA client automatically sends eight same-host POST XHR requests to:

`/awsgetcontentareas.aspx`

TASK 219J inspected only those requests already generated by the page and their already-received responses, without causing any direct call to the route.

## Runtime boundary

The run used exactly one clean browser session and one initial navigation.

It performed:

- zero clicks;
- zero typing;
- zero form submissions;
- zero manual XHR/fetch;
- zero direct endpoint calls;
- zero authentication/session injection;
- zero retries.

DevTools was used only to read request data the page had already sent and response bodies the browser had already received.

Raw POST values, response text and raw HAR were never persisted.

## Request contract discovered

All eight automatic requests used exactly the same outer request contract:

- method: **POST**
- route: `/awsgetcontentareas.aspx`
- content type: `application/x-www-form-urlencoded; charset=UTF-8`
- initiator: script
- field count: **1**
- field name: **`LayerInfo`**

The only field, `LayerInfo`, was classified as TEXT in all eight calls.

Observed lengths, without preserving values:

- 3,799
- 3,793
- 3,793
- 3,224
- 3,792
- 3,807
- 3,954
- 3,119 characters

Therefore `LayerInfo` is not supported as a simple scalar area identifier. It is a large page-generated serialized text document whose internal schema remains unknown.

## Response structure

All eight responses were:

- HTTP 200;
- HTTP/2;
- MIME `text/html`;
- captured successfully for sanitized structural analysis.

All eight body hashes are different.

Observed body sizes ranged from **1,177 bytes** to **368,638 bytes**.

The bounded literal HTML parser found no start tags in seven responses and only `i` / `li` in one response. Therefore the declared MIME cannot safely be interpreted as a normal HTML fragment. The response serialization/schema remains unproven.

No response text or body source is stored in the repository.

## Scientific meaning

TASK 219J proves the **outer browser-generated transport contract**:

`POST /awsgetcontentareas.aspx`
→ form-urlencoded
→ one field named `LayerInfo`
→ large page-generated serialized text
→ distinct HTTP 200 responses.

It does **not** prove:

- the internal keys or semantics of `LayerInfo`;
- that `/awsgetcontentareas.aspx` is an accounting endpoint;
- a direct machine-call contract;
- a query for Empenho 3286-2026;
- linkage to Contract 45/2026;
- payment attribution.

The correct engineering consequence is to avoid synthesizing or guessing `LayerInfo`.
